`src/` is the single application (UI + API).

## Start the app

Prerequisites: Node.js 24 (`nvm use` picks it up from `.nvmrc`).

```bash
npm ci
copy .env.example .env        # then set AIRNOW_API_KEY / NASA_FIRMS_API_KEY if needed
npm run dev                   # http://localhost:3000 — globe UI at /, API at /api/*
```

Provider keys (`AIRNOW_API_KEY`, `NASA_FIRMS_API_KEY`) are optional; without them the affected layers return clearly-labelled `SIMULATED` data. The UI calls same-origin `/api/v1` — no `VITE_API_BASE_URL`, no CORS.

## Diagnosing production connectivity

1. Open the deployed app → Settings → Diagnostics. It shows the configured API base + source, backend health + latency, current layer/provenance, the server-cache hit/miss (L1 `meta.cache_hit` only — never inferred from SWR), the OS motion preference, WebGPU support, and the active renderer. `Copy report` copies exactly the displayed rows (no secrets, no key-bearing URLs) for pasting into a troubleshooting note; clipboard failure shows a status message instead of throwing.
2. If `Backend health` reads `unreachable`, check the Vercel deployment (failed build, missing env vars). There is no CORS layer — same-origin requests cannot fail on CORS. (The old `API base: not configured` state no longer exists: the base is the constant `/api/v1`.)
3. `GET /api/health` and `GET /api/v1/health` must both return `{ status: "ok", … }`; `GET /api/v1` must return the `{ version, links }` index; `GET /api/v1/layers` must list the 8 layers. Health carries `started_at` (ISO 8601 instance-local boot time, captured at module load — not deployment time; it resets per serverless isolate, which is why the old `uptime_seconds` was removed).

## Earth renderer

- `components/globe/dotted/DottedEarth.tsx` — **default renderer (GLOBE-1)**: a 2D-canvas orthographic Earth mounted inside the stage cell by `components/shell/GlobeStage.tsx`. No GPU probe, no WebGL/WebGPU context, no textures: the ocean disc + graticule paint on the first frame, and the land dots + coastline appear the moment the *local* geography asset resolves. Always visible — deliberately **not** gated on `activeLayer`, on layer loading, or on whether the layer returned points (an empty data layer is not an empty Earth). Drag, wheel zoom, hover/click picking and fly-to live here; markers reuse `filterValidPoints`, so rendered marker N is always data point N.
- `components/globe/rendererMode.ts` — the single decision point: `resolveGlobeMode()` returns the `?renderer=` override or `DEFAULT_GLOBE_MODE = 'dotted'`. Components read it through `useSyncExternalStore` (`useGlobeMode()`), so SSR reports the neutral `'pending'` (loading veil, pinned by `page.test.tsx`) while the client resolves synchronously — no capability probe, no cascading `setState`, no hydration mismatch.
- `components/globe/EarthRenderer.tsx` — mounts the fullscreen fixed container **only** for `?renderer=webgpu` / `?renderer=webgl`; in the default mode it returns `null` so the stage globe is the only Earth on screen (it can no longer paint a black layer over it). The existing WebGPU → WebGL graceful fallback is preserved and layered on top: chunk-load failure, `WebGPUEarth` error, and a 30 s init watchdog all degrade to WebGL instead of holding a blank canvas.
- `components/globe/WebGPUEarth.tsx` — WebGPU + TSL Earth (Three.js 0.185.x: `three/webgpu`, `three/tsl`, OrbitControls from `three/addons`). Imperative engine in a mount-once effect; props flow through refs so the frame loop never sets React state. Full cleanup on unmount. Opt-in only.
- `lib/webgpu.ts` — `getForcedRenderer()` reads the `?renderer=` override; `probeWebGpuSupport()` / `decideRendererMode()` stay unit-tested but are no longer on the default path.
- Manual GPU validation cannot run in Vitest/jsdom: verify in a real browser (see root README → Earth Renderer).

### Texture pipeline and resolution tiers (T4.1)

- **Inventory (`public/textures/`, NASA Visible Earth Blue Marble family, public domain):** day `earth-day.jpg` 4096×2048 JPEG 1.46 MB (color map) · night `earth-night.jpg` 4096×2048 JPEG 715 KB (city lights) · clouds `earth-clouds.jpg` 2048×1024 JPEG 809 KB, alpha-free additive shell (renamed from `.png` in T4.1 — the bytes were always JPEG, now served as `image/jpeg`) · topology `earth-topology.png` 2048×1024 gray 378 KB (normal/bump) · water `earth-water.png` 1600×800 RGB 430 KB (specular/roughness). The dotted Earth uses none of these (its only asset is the GeoJSON geography above).
- **Tiers (`src/components/globe/textureTiers.ts`, the single decision point):** `standard` = 2K day/night derivatives (`earth-day-2k.jpg` 404 KB, `earth-night-2k.jpg` 195 KB; high-quality bicubic downsamples of the 4K originals, JPEG q90) + shared companions → **2.13 MiB**; `high` = 4K originals + same companions → **3.64 MiB**. Both tiers meet the PRD 6 MB default-load budget (measured by `npm run textures:report`, which exits nonzero on missing assets or budget breach). Estimated GPU allocation (decoded RGBA8 + mips, reported separately from file bytes): ~49 MiB standard vs ~113 MiB high.
- **Selection (conservative, stable per renderer lifetime):** high requires *all of* fine pointer, no Save-Data, DPR ≥ 1.5, screen ≥ 1600 px, `deviceMemory` ≥ 4 GB when known, and `maxTextureSize` ≥ 4096 when known (unknown signals never veto except DPR/screen, which default to standard). WebGPU alone is never treated as proof of GPU memory; both renderers consume the same manifest, so no path can diverge. The drei path resolves via `useTextureTier()` (SSR snapshot `standard`, same pattern as `useGlobeMode` — one download, no upgrade); the imperative path resolves once at init.
- **Fallbacks:** per-texture standard-URL retry on preferred-asset failure (`loadTieredTexture`), then the existing renderer chain (chunk failure / engine error / 30 s watchdog → WebGL). Tier never changes mid-life, so both sets are never allocated together; teardown disposal is unchanged.
- **KTX2 decision (documented trade-off):** rejected — no transcoder toolchain in this repo/CI to produce `.ktx2` assets, ~584 KB of in-package transcoder overhead (`three/examples/jsm/libs/basis/`, never shipped), and a per-platform format matrix the WebGPU path cannot verify headlessly. JPEG/PNG decode universally with zero new dependencies; no runtime CDN fetches (CSP `img-src 'self'`).
- **Validation:** `npm run textures:report` (reproducible payload accounting) plus `next start` + `HEAD` checks per URL for status/MIME/size (see T4.1 task record). Visual parity, seams, day/night/clouds look, both GPU modes, and failure-path behaviour are owner-manual (no screenshots, GPU, or E2E automation in CI).

### Render-loop discipline (T4.2)

- **Shared gate (`src/lib/motion.ts`, `frameLoopActive`):** a frame is earned by an interpolating flight or a held drag; ambient rotation only when the user switch is on *and* the OS allows motion. All engines share it, so idle means idle everywhere. Deltas stay clamped (0.1 s) on every path — background pauses can never cause jumps.
- **Dotted Earth (already disciplined, verified not changed):** gated `tick` reschedules only while active; `visibilitychange` cancels rAF on hide and redraws once (with a clock reset) on show; in-progress flights freeze and resume instead of teleporting; full listener/rAF cleanup on unmount. Pinned by `DottedEarth.loop.test.tsx` (idle settle, rotate perpetuation + toggle-off, hidden pause/resume with frozen flight, drag demand, unmount silence, mount churn).
- **WebGL/R3F (`frameloop="demand"` in `GlobeScene`):** frames render on `invalidate()` only. Self-perpetuation while a flight/rotation continues (gate at the end of `useFrame`); cloud drift follows the auto-rotate gate (a rotation-paused globe is fully still — drift never forces a loop); explicit invalidates on data/flight/toggle/motion/sun changes, texture resolution, resize, and visibility return; drag/zoom/damping flow through drei (`change` → invalidate). Hover changes no pixels, so it schedules nothing. Reduced motion freezes rotation, drift and starfield and turns fly-to into a jump, as before.
- **WebGPU (imperative `ensureLoop` gate in `WebGPUEarth`):** `setAnimationLoop` runs only while `frameActive()` holds and stops itself otherwise — the stopped canvas keeps its last presented frame. Every wake source funnels through one primitive: pointer drag (up/cancel/click/leave always release it, so the gate cannot stick), controls change/start (covers damping tails), resize, visibility return (clock reset + one frame), marker/sun/flight updates, and control-preference flips via a `wakeLoopRef` handle. Cloud drift follows the same activity gate. Teardown stops the loop and removes every listener; init-failure and watchdog paths are untouched.
- **What unit tests prove (and do not):** scheduling contracts (loop settles/resumes, no duplicate loops, cleanup returns to baseline) are pinned headlessly; `EarthRenderer` fallback, URL, provenance and app suites guard the contracts around them. Frame rates, GPU memory behaviour and visual equivalence need a real browser + GPU — owner-manual, same standing as all visual items.

### Initial JavaScript bundle budget (T4.5)

- **Budget:** initial-route JavaScript for `/` ≤ **200 KiB gzip (204,800 bytes)**, excluding only the lazily loaded globe chunks. Measured per file with Node zlib level 6 (the Node/Vercel default) and summed — browsers download the files separately, so there is no cross-file compression. The budget reading of "KB" is KiB (1024).
- **What counts:** exactly the JavaScript files in the production `app-build-manifest.json` `pages["/page"]` list (the files Next.js schedules for the route), deduplicated. Shared/runtime chunks stay counted. Source maps, CSS, images, API payloads, textures and GPU estimates are never part of this budget.
- **What is excluded and why:** only the two genuinely lazy 3D globe chunks — `EarthRenderer.tsx -> ./WebGPUEarth` and `EarthRenderer.tsx -> ./GlobeScene` from `react-loadable-manifest.json` (matched on the import-graph key, never on filenames). Both 3D renderers are opt-in (`?renderer=` / WebGPU→WebGL fallback behind a loading veil); the default dotted Earth renders without them. The lazy chunks are verified absent from the counted set on every run — if one ever lands in the initial set, the check fails (regressed code-split) instead of hiding it. The legacy-only `noModule` polyfill chunk (~40 KiB gzip, skipped by evergreen browsers) is not counted; add it mentally if legacy support matters.
- **How it got under budget (no threshold or exclusion gaming):** the baseline was 440.3 KiB gzip — the initial route downloaded three.js without executing it. Two behavior-preserving changes fixed that: (1) `GlobeScene` (three + R3F + drei) became a lazy `ssr:false` chunk like `WebGPUEarth` (`?renderer=webgl` shows the same veil-then-globe pattern); (2) `src/lib/geo.ts` dropped its `three` import for plain `Vec3`/`Quat` math (parity against the real three.js implementation pinned in `geo.test.ts`), evicting the three.js core from the initial chunk graph. Result: **193.5 KiB gzip** (6 files), margin ~6.7 KiB — thin by construction, which is exactly what the gate guards. See `docs/audit/bundle-budget.md` for the before/after tables.
- **Commands:** `npm run bundle:check` (after `npm run build`; exits 1 on breach, 2 on accounting failure). CI runs it after the build step against that exact build output — a breach or a missing/ambiguous manifest fails the job. Logic tests live in `src/lib/bundle-budget.test.ts` (fixture manifests only; the production verdict always comes from real `.next` output).
- **Limitations:** file-level gzip is a transfer-size proxy, not a browser measurement — it says nothing about LCP/FCP, Web Vitals, parse/compile cost, FPS or GPU memory (all owner-manual). Byte output can shift slightly across Node/zlib versions; CI (Node 24) is the reference. Do not raise the budget or widen exclusions without owner approval.

### Base geography asset (GLOBE-1)

- `public/geo/land-110m.json` — Natural Earth `ne_110m_land` (127 polygons), stripped to `{ type, features[].geometry }` (126 KB). Same-origin static asset, fetched **once per session** by `dotted/landGeo.ts`: concurrent callers share one in-flight promise, a settled success is cached, a failure is never cached (so a transient error may be retried), and a non-FeatureCollection payload rejects instead of poisoning the projection. Public domain — source, processing notes and terms in `public/geo/NOTICE.md`.
- `dotted/dotField.ts` — the land dot field is built **once** after the asset resolves (Fibonacci sphere + `geoContains`), never inside the frame loop; `DOT_FIELD_CANDIDATES = 3600` yields roughly 1000 land dots.
- `dotted/globeProjection.ts` — hand-rolled rotate + orthographic projection with a depth test, asserted for parity against a real `geoOrthographic()` in `globeProjection.test.ts`. The depth test is required because `projection(point)` bypasses d3's clip pipeline, which would mirror far-side land into the disc.

All `/api/*` routes keep their own `force-dynamic`. ## URL-driven application state (T3.3)

- **Contract:** `?layer=<id>&event=<id>&q=<text>&sev=<level>&view=globe|list`, implemented in `src/lib/url-state.ts` (pure parse/serialize/validate — no React, window, or provider calls) and orchestrated by `useAppUrlState` in `src/components/app/` (mount restore, state→URL sync, `popstate` Back/Forward). No `useSearchParams`, no `force-dynamic`, no state library; `window.history` push/replace keeps App Router out of the loop (no RSC refetch, no `router.refresh()`).
- **Allowed values:** `layer` ∈ the 8 `LAYER_IDS` (absent/invalid → T3.8 first-run default `earthquakes`, applied client-only after mount; explicit valid `?layer=` always wins); `event` ∈ the events-route id rules (`fire-` ids additionally coordinate-validated; resolved against loaded layer data, never fabricated); `q` follows the T1.5 input rules (trimmed, 2–200 chars, no control characters); `sev` ∈ `all|low|moderate|high|critical` (display-only filter, lifted from `LayerOverview` to the shell); `view` ∈ `globe|list` (default `globe`; the header `View` toggle (T3.15) switches the stage between the globe and the primary event list — both read the same `useLayerData` payload, no second fetch path).
- **Invalid/default behavior:** invalid values are dropped (junk never reaches provider calls — an absent/invalid `layer` instead resolves to the validated T3.8 default `earthquakes`); defaults omitted from the canonical URL (`layer`/`event` null, `q` empty, `sev=all`, `view=globe`) except the applied first-run default, which is recorded as `?layer=earthquakes`; unknown params — notably `renderer` — ride along verbatim. Serialization order is fixed (`layer,event,q,sev,view`) and parse→serialize is a fixed point, which keeps sync loop-free.
- **History:** discrete navigations (layer/event/sev/view) `push` Back-restorable entries; query typing `replace`s (no per-character entries); mount/popstate canonicalization replaces. Back from an event closes its detail (state re-applied from the URL); Forward restores it. Layer switches always clear conflicting event selection.
- **Examples:** `/?layer=earthquakes`, `/?layer=earthquakes&event=usgs-12345`, `/?layer=wildfires&q=fire&sev=high&view=list`, `/?layer=disasters&event=eonet-123&renderer=webgl`.
- **Limitations:** `q` values under 2 chars don't survive reloads (search needs ≥2); event restore requires its layer's data to contain the id (stale ids are dropped from the URL, never synthesized).

## Application composition (T3.17)

- `SentinelApp` (`src/components/app/SentinelApp.tsx`) is the thin composition root: it wires focused hooks into the shell regions (header / rail / stage / panel / status / overlays) and owns only local presentation wiring (hover, settings open, rotation, points mirror, renderer info, four navigation callbacks, keyboard map wiring). All orchestration lives in `src/components/app/`:
  - `useAppUrlState` — URL↔state sync, first-run default, push/replace conventions, popstate (pure parsing stays in `src/lib/url-state.ts`).
  - `useEventSelection` — selected marker + race-safe, abortable detail fetch.
  - `usePendingEventResolution` — deep-link id resolved against fresh layer data (or dropped, never fabricated).
  - `useFocusRestore` — focus request/apply lifecycle + surface checks.
  - `useFirstRunHint` / `useSingleKeyShortcuts` — persisted client-only flags (hint dismissal, shortcut master switch).
  - `useFlyTo` — validated camera-flight destination with retrigger key.
- Creation order is load-bearing (documented in `SentinelApp`): selection takes a stable layer ref, the URL hook takes the selection callbacks, data hooks take the URL hook's layer, and pending resolution is declared last. The layer ref mirror applies before resolution so same-flush restores observe the current layer.
- **T3.18 audit outcome:** the remaining ~305-line composition root (hook wiring, four navigation callbacks, keyboard map, eight region JSX subtrees) was audited for further boundaries and deliberately left intact — workspace/overlay/frame splits would only drill props without owning logic (see `phase-3-review-gates.md` §5). No orchestration logic was moved back into `SentinelApp`.

## Layer data client (T3.6)

- **Typed hook:** `useLayerData(layerId, options)` in `src/hooks/useLayers.ts` (SWR `2.5.1`, the owner-chosen client fetch library — no other state-management library was added). Returns `{ data, loading, validating, error, dataStatus, meta, refetch }`: `data` is the `LayerData` payload (or `null`), `loading` covers initial load + revalidation (existing refetch-spinner UX), `validating` flags background revalidation, `error` is the `ApiError` below (or `null`), `dataStatus` is the payload's `data_status` provenance (or `null`), `meta` carries the server envelope's `cache_hit` as `cacheHit` (`null` without data), and `refetch` triggers `mutate()`. `SentinelApp` maps `error` to `error.message` for `DataPanel` (`string | null`); event detail still uses `api.getEvent` directly (out of scope).
- **Single typed path:** all layer-data requests go through `api.fetchLayerDataPath` / `api.getLayerDataEnvelope` in `src/services/api.ts`, which preserve the `{ success, data, meta }` envelope and `meta` (server `cache_hit`, `fetched_at`, source, `data_status`). No component builds layer-data URLs: the SWR key **is** the request path, built by the single `buildLayerDataPath` helper (same param order, falsy values omitted — existing semantics unchanged). Search/geocoding/stats clients are untouched.
- **Cache-key structure:** `buildLayerDataKey(layerId, params)` returns the canonical path or `null` (which disables fetching — no request, no error). Keys use authoritative `LAYER_IDS` (unknown ids → `null`), normalized params (limit clamped to 1–2000, default 500 materialized so absent/undefined agree; `min_severity` allow-listed to `low|moderate|high|critical`, invalid values dropped — never broadened; `bbox` validated by the shared `parseBbox`, malformed → `null`), so equivalent normalized parameters always yield identical keys and every response-affecting parameter is in the key. No credentials or secrets enter keys (there are none client-side; all keys are server-side only).
- **Deduplication:** SWR `dedupingInterval: 2000` — identical concurrent keys share one network request across consumers; `revalidateOnFocus: false` (heavy-route quota protection; explicit Refresh exists), `revalidateOnReconnect: true`, no interval polling. Same-key revalidation keeps current data visible; `keepPreviousData: false` so a layer switch never shows the previous layer's markers labelled as the new layer (new key → `data: null` + `loading: true` until the fresh response lands).
- **Cancellation:** a ref-counted per-key `AbortController` registry — the last consumer to release a key aborts its fetch; one consumer leaving never kills another consumer's shared request. The signal reaches `fetch` via the existing client timeout/signal-merge path. Limitation: browser-side abort stops client work only — it does not guarantee provider work halts server-side (no cancellation propagation beyond the existing T2.2 upstream timeouts; routes wire no caller signal yet). Server-side T2.2 behavior is preserved untouched.
- **Retry/backoff (bounded, documented):** custom `onErrorRetry` — at most `LAYER_RETRY_MAX_ATTEMPTS=3` retries for transient failures (network-level `ApiError` without status, HTTP 5xx) with exponential backoff `500 → 1000 → 2000 ms` + ≤250 ms jitter, capped at 8000 ms; HTTP 429 gets at most `LAYER_429_MAX_ATTEMPTS=2` extra attempts paced by `Retry-After` (delta-seconds or HTTP date, parsed server-side-capped at 60 s, client-capped at 30 s wait); 400/404 and other 4xx are never retried; caller aborts and client timeouts are never retried (slow heavy routes must not multiply load — the user refreshes explicitly); obsolete keys (layer switched mid-backoff) and unmounted components never refire; a successful response carrying simulated data is data, not a failure — never retried. The backend T1.3 limiter stays authoritative; client retries stay far inside its budget.
- **Cache-layer roles (separate entries, never conflated):** in-memory SWR cache (per-key client dedupe/revalidation, `cacheHit: null` side) vs server L1 `MemoryCache` (per-instance TTL + stale re-serve, reported as `meta.cacheHit` + `fetched_at`) vs HTTP/CDN (`Cache-Control: public, s-maxage=<TTL>, stale-while-revalidate` on LIVE only, T2.1). `data_status` (`live|stale|simulated|unavailable`), `source`, `fetched_at`, and `Cache-Control`/fallback semantics are preserved verbatim — no timestamps invented, no headers altered for SWR.
- **Provenance/status handling:** `live`/`stale`/`simulated`/`unavailable` pass through distinctly (never relabelled, never retried); empty live results (`points: []`) are valid, not errors; failures surface as `ApiError` (`message` preserved, plus `status`/`code`/`retryAfterSec`) so existing `toThrow(message)` expectations hold. Existing `DataStatusBanner`/chips/dock displays are reused unchanged; any state the current UI cannot yet distinguish is exposed correctly through the hook (no missing-presentation follow-ups were found — all four statuses, empty, loading, and error shapes already render).
- **Idle prefetch (conservative, bounded):** exactly one candidate — `earthquakes` (the T3.8-designated default; most likely next selection from first-run) — scheduled once via `requestIdleCallback` (5 s timeout; 3 s `setTimeout` fallback), skipped when the candidate is active, the tab is hidden, or the client is offline; cancelled on layer change/unmount; silent on failure; uses the canonical key + shared fetcher so a later selection hits SWR cache with zero new traffic. One key, one attempt, no retries — never every layer, never invalid/unvalidated params, never against heavy-route pressure beyond one light `limit=500` request.
- **Known limitations:** SWR cache is in-memory per page load (no persistence); prefetch covers only the default layer (no predictive framework); abort cannot stop server-side provider work; `min_severity` values outside the allow-list are silently dropped to unfiltered rather than rejected (matches existing server-side optional-param semantics).

## Data provenance UI (T3.7)

- **Mapping (`src/lib/provenance.ts`, pure `resolveProvenance`):** `LIVE` = `data_status.status: live` with `meta.cache_hit !== true`; `CACHED` = `live` + `cache_hit === true` (the ONLY thing that may render CACHED — SWR/client caching never implies it); `STALE`/`SIMULATED`/`UNAVAILABLE` pass through verbatim (a stale re-serve with `cache_hit: true` still reads STALE); `ERROR` = failed request with no usable payload (kept distinct from successful `simulated`/`unavailable` responses); `UNKNOWN` = no payload and no failure (initial load / layer switch). No API semantics changed: envelope, `data_status`, `source`, `fetched_at`, and `meta.cache_hit` meanings are untouched.
- **Strip (`src/components/overlays/DataStatusBanner.tsx`):** compact provenance area inside `DataPanel` (plus the detail-view `EventDetails` travel-strip and the `AppHeader`/`StatusDock`/Diagnostics chips via `provenanceChipLabel`). Every state carries a text label (never colour alone), the real `source` (`Unknown source` when missing/blank — never invented), and an age derived only from the real `fetched_at` (`formatAge` in `src/lib/format.ts`; missing/invalid → explicit `age unknown`; request time is never substituted). `role="status"` announces on change; the ticking age readout is `aria-hidden` with a tick-stable `aria-label` (absolute `Data fetched <date> UTC`) so revalidation never re-announces.
- **Freshness safety:** the client clock starts after mount (30 s interval, cleared on unmount; SSR markup stays deterministic — pinned by a `renderToString` test), so there are no server/client mismatches. Same-key revalidation keeps data + provenance (an error alongside a payload never relabels it); layer switches yield `data: null`/`dataStatus: null` (`keepPreviousData: false`, T3.6), so the strip reads UNKNOWN — previous-layer provenance can never linger.
- **Tests:** `src/lib/provenance.test.ts` (mapping), `DataStatusBanner.test.tsx` (all states, LIVE-vs-CACHED, timestamps, source, SSR safety, cadence), `format.test.ts` (`formatAge`), `DataPanel.test.tsx` (layer-switch + error provenance). Hook-level switch/revalidation behavior stays covered in `src/hooks/useLayers.test.tsx`.

## First-run experience (T3.8)

- **Default layer:** `DEFAULT_FIRST_RUN_LAYER = 'earthquakes'` (`src/lib/url-state.ts`, owner-locked). ## Deployment overview

- **Single Vercel project (repo root):** framework Next.js, build `npm run build`. Set server-only `AIRNOW_API_KEY` / `NASA_FIRMS_API_KEY` (never `NEXT_PUBLIC_`). No Render, no separate frontend deployment, no CORS, no scheduler. The UI (`/`) and API (`/api/*`) ship together.

## Where integrations live

- **Provider integrations:** `src/server/providers/` — one adapter per upstream (`usgs`, `nasa-eonet`, `nasa-firms`, `open-meteo`, `airnow`, `geocoding` for Open-Meteo forward search), plus `heatmap`, `fallback`, `imagery`, `geocode` (offline IANA timezone lookup via `@photostructure/tz-lookup`). Dispatch + cache + stale-fallback live in `src/server/services/layers.ts`. Individual event lookup lives in `src/server/services/event-detail.ts`: an explicit id resolver routes raw ids to the USGS detail feed, `eonet-*` ids to the EONET event endpoint, and `fire-<lat>-<lon>` marker ids to the live FIRMS observation detail below; everything else (mock markers, other layers) goes to labelled simulated detail. No database is required — details are fetched on demand and cached briefly per instance.
- **Frontend API integration:** `src/services/api.ts` — the single client boundary (same-origin `/api/v1` base, timeout, cancellation, error normalization; `ApiError` carries `status`/`code`/`Retry-After` for the retry policy). Components never call `fetch` directly. Layer data is consumed through the typed SWR hook `useLayerData` in `src/hooks/useLayers.ts` (see "Layer data client (T3.6)" below); the SWR key is the canonical request path, so key and URL cannot diverge.
- **Globe:** `src/components/globe/` — `EarthRenderer.tsx` mounts the WebGPU `WebGPUEarth.tsx` (`three/webgpu` + TSL) or the WebGL `Globe`/`GlobeScene` (three + R3F + drei) branch, **both** `next/dynamic ssr:false` code-split (T4.5: the default dotted Earth must not download three.js on first load). Rendering code is production-sensitive: do not rewrite the scene, textures, markers, controls, or animation loop. Textures live in `public/textures/`.
- **Provenance:** every payload carries `data_status` (`live` / `simulated` / `stale` / `unavailable`); see `src/server/provenance.ts` and `src/components/overlays/DataStatusBanner.tsx`.

## Current caching approach

Per-instance in-memory TTL store with stale fallback (`src/server/cache.ts`, `FALLBACK_TTL=60`, `STALE` re-serve of expired live entries on refresh failure). Vercel serverless instances are ephemeral, so the cache is a best-effort per-instance optimization, never the source of truth. **No database or Redis is required** — the app visualizes externally-owned provider data rather than persisting its own dataset.

## HTTP caching (T2.1)

Successful `LIVE` or static-catalogue responses carry `Cache-Control: public, s-maxage=<TTL>, stale-while-revalidate=<2 × TTL>` (helpers in `src/server/route-helpers.ts`). Everything else — errors, throttles, health, and stale/simulated fallbacks — carries `no-store`, so a shared cache never extends data that must stay current or was never live. Responses do not vary by request headers (no auth/cookies/content negotiation); query strings already differentiate shared-cache keys.

| Endpoint / layer | TTL (s-maxage) | Stale-while-revalidate | Policy rationale |
|---|---:|---:|---|
| `GET /api/v1/layers/<id>/data` — LIVE | per-layer `LAYER_TTLS` (300 quakes/disasters, 600 wildfires, 1800 clouds/wind/air_quality, 3600 temp/precip) | 2 × TTL | mirrors the in-memory TTL for live provider data |
| `GET /api/v1/search` — LIVE merged results | 300 (`SEARCH_TTL`) | 600 | exact-query key; bounds repeat upstream fan-out from debounced typeahead + shared-cache clients |
| `GET /api/v1/stats` — LIVE overview | 300 (`STATS_TTL`) | 600 | 3 parallel single-request source fetches; key is the fixed trailing window |
| `GET /api/v1/stats/historical` — LIVE series | 300 (`STATS_TTL`) | 600 | key embeds metric + period (the only content-determining params); sliding windows stay honest via `fetched_at` |
| `GET /api/v1/timezones` — LIVE (offline lookup) | `no-store` | — | payload embeds current wall-clock time/offset (per-second staleness); lookup is in-process sync, so no cache entry is needed either |
| `GET /api/v1/events/<id>` — LIVE | 300 (`EVENT_DETAIL_TTL`) | 600 | live USGS/EONET detail, same TTL as the memory cache |
| `GET /api/v1/layers` | 3600 | 7200 | static code-defined catalogue, changes only on deploy |
| `GET /api/v1/imagery/gibs/capabilities` | 3600 | 7200 | static 3-layer catalogue |
| `GET /api/v1` (index) | 60 | 120 | static version + links; short TTL keeps `meta.timestamp` fresh |
| Health (`/api/health`, `/api/v1/health`) | `no-store` | — | per-isolate `started_at`/timestamp must remain current |
| Layer data / heatmap / event detail when STALE or SIMULATED | `no-store` | — | never extend fallback data through a shared cache |
| Search (STALE re-serve, SIMULATED event fallback, UNAVAILABLE), stats overview / historical series (STALE re-serve, UNAVAILABLE), reverse geocode (always UNAVAILABLE) | `no-store` | — | fallbacks and unavailable results are never extended via CDN |
| GIBS tile 302 redirect | (unchanged, no policy) | — | `Location` embeds the current date; upstream owns tile caching |
| 400 / 404 / 500 (`fail`/`notFound`/`internalError`) | `no-store` | — | invalid-input and internal errors are never public data |
| 429 (middleware) | `no-store` (+ `Retry-After`) | — | per-client throttle decisions, never cached as success |

How the layers interact:

- **In-memory L1** (`MemoryCache`): per-instance, keyed by full query (`layerCacheKey`/`heatmapCacheKey`/`eventCacheKey`). Only `LIVE` payloads get the full TTL; simulated payloads get `min(60, TTL)`; expired `LIVE` entries are re-served as `STALE` when refresh yields simulated data. `meta.cache_hit` reports the L1 outcome (`true` on fresh hit or stale re-serve); `fetched_at` is the provider fetch time and never moves on cache hits.
- **HTTP L2** (CDN/shared cache): applies only to the rows marked public above, with TTLs aligned to the L1 TTLs, so both layers expire together. `meta.timestamp` is the origin response time and legitimately lags on CDN-served responses.
- **Upstream `fetch` revalidation was evaluated and rejected:** provider fetches (`src/server/http.ts`) use plain `fetch` with no `next: { revalidate }`. A fetch cache would duplicate the L1 (same per-instance scope) while losing stale-fallback and provenance semantics, so no second cache layer was added.

Limitations (do not overclaim):

- No Vercel cache hit is claimed without deployment evidence (`x-vercel-cache` headers); local `next start` verification below proves origin headers only.
- Serverless isolates each hold their own L1; a cold isolate refetches from providers on first miss.
- CDN-served responses bypass the origin handler entirely, so origin-side (T1.3) rate limiting is defense-in-depth, not a global abuse-control guarantee — pair with a Vercel Firewall rule when the plan allows it.

## Provider timeouts + bounded concurrency (T2.2)
- **Default upstream timeout: 8 s** (`REQUEST_TIMEOUT`, was 15 s). Every provider fetch goes through `fetchJsonWithTimeout` (`src/server/http.ts`), which aborts the request on the deadline, cleans up its timer and abort listener, and throws `UpstreamTimeoutError` — distinct from HTTP error statuses (returned, not thrown) and connection failures (propagated unwrapped). A pre-aborted caller signal propagates as cancellation without starting work. Timeout messages are redacted at construction (T1.4): configured key values are scrubbed even as URL path segments, query-param credentials by pattern.
- **Per-provider overrides (seconds):** `USGS_TIMEOUT`, `EONET_TIMEOUT`, `OPEN_METEO_TIMEOUT`, `AIRNOW_TIMEOUT`, `FIRMS_TIMEOUT` — each falls back to the global default. Values are validated: malformed or `< 1` → default; `> 30` clamps to `MAX_UPSTREAM_TIMEOUT_SEC=30`, so no override can outrun the route ceilings below.
- **Open-Meteo bounded concurrency:** the grid (108 points global 12×9, 100 per bbox 10×10) is sliced to `min(limit, MAX_FETCH_POINTS=200)` in 50-point batches (upstream batch contract, unchanged), dispatched through a 2-worker pool (`BATCH_CONCURRENCY=2`, `src/server/providers/open-meteo.ts`). No provider quota is claimed: 2 is a small multiple of the previous serial dispatch — worst case drops from 4 sequential batch timeouts to 2 waves (≤ ~16 s), while never fanning out unboundedly (at most 4 batches exist). Results re-associate by chunk index, so coordinate ordering is preserved; scheduling stops once a caller signal aborts; an optional `signal` is accepted by `getWeatherData` (routes do not wire one yet — client-disconnect cancellation is future work).
- **Partial failures:** a failed batch keeps its successful siblings. Live-but-incomplete results stay `LIVE` with the same source/`fetched_at`, plus `warnings[]` and a `data_status.message` of the form "Partial live coverage: N of M grid points could not be fetched; …" — never presented as complete. Batches that omit a point's value are coverage gaps (counted, skipped), never invented zeros. All batches failing keeps the existing hierarchy: valid stale re-serve if allowed, else labelled `SIMULATED` (timeout → simulated + `no-store` per T2.1, since the policy keys on status).
- **Route `maxDuration` inventory:**

| Route | Upstream ops | Worst case by construction | Configured | Evidence |
|---|---|---:|---:|---|
| `GET /api/v1/layers/<id>/data` | weather: ≤4 batches @ conc. 2 × 8 s; others: 1 fetch ≤ 8 s | ~16 s + overhead | `maxDuration = 30` (~2× headroom) | Vercel docs 2026: Hobby Node.js functions 300 s default/maximum |
| `GET /api/v1/search` | 1 geocoding request ≤ 8 s (count ≤ 10, no paging) | ~8 s + merge | none (platform default applies) | single bounded request, far under ceilings |
| `GET /api/v1/stats` | 3 parallel single-request source fetches, each ≤ 8 s | ~8 s wall + aggregate | none (platform default applies) | bounded fan-out of 3, far under ceilings |
| `GET /api/v1/stats/historical` | 1 request per metric (USGS/EONET/FIRMS), each ≤ 8 s | ~8 s + bucket | none (platform default applies) | single bounded request; FIRMS rows capped at 200k, USGS at the service 20k cap |
| heatmap, geocode, timezones, layers, capabilities, tile, health, index | none (local compute / static / redirect / offline sync lookup) | < 1 s | none (platform default applies) | no upstream fan-out to bound |
| `GET /api/v1/events/<id>` | 1 detail fetch ≤ 8 s | ~8 s + normalize | `maxDuration = 15` (~2× headroom) | same Hobby cap |

- **Known platform limits:** the 300 s Hobby cap is verified from Vercel's public docs (2026), not from dashboard access — plan-specific behavior (e.g., a future Pro move) must be re-verified by the owner. `maxDuration` is a backstop only; per-batch timeouts remain the primary bound. No Redis/workers/queues were added.

## Wildfire detail from FIRMS observations (T2.3)

- **Marker association:** wildfire markers carry `fire-<lat>-<lon>` ids built from the observation's parsed coordinates, so the detail lookup re-associates the exact feed row by numeric coordinate match — no payload is embedded in the id and no marker change was needed. Repeat overpasses at identical coordinates resolve to the latest acquisition. Malformed fire ids (`fire-abc`, out-of-range, …) are rejected with `400` before any provider call; the `fire-` namespace never accepts upstream URLs.
- **Exposed fields:** `brightness` (bright_ti4), `frp`, `confidence`, `daynight`, `satellite`, `instrument`, `acq_date`, `acq_time` (combined into `timestamp`), `lat`/`lon`, plus FIRMS source attribution. Absent optionals are `null`; rows without numeric brightness cannot yield an honest detail. Brightness/FRP describe the thermal signal, not fire size or burned area.
- **Status meanings for wildfire detail:** `live` = built from a successfully fetched feed row (source `NASA FIRMS`, cached 5 min, publicly cacheable per T2.1); `stale` = expired live re-served after a refresh failure; `simulated` = keyless instance, fetch failure, malformed feed, or marker no longer in the 24 h feed window (never publicly cached). No key → no fetch is ever attempted.

## Real search, reverse geocode, and timezones (T2.6)
- **Forward search (`src/server/providers/geocoding.ts`, route `src/app/api/v1/search/route.ts`):** live locations from Open-Meteo Geocoding (`https://geocoding-api.open-meteo.com/v1/search`, override `OPEN_METEO_GEOCODING_URL`; contract verified in official docs — `name`/`count` 1–100/`language=en`, 2-char exact / 3+-char prefix matching, postal codes accepted, `{error, reason}` on 400, GeoNames-based data, no key for non-commercial use). One request per route call, `count = min(limit, 10)` (no 100-result paging), shared timeout helper (`OPEN_METEO_TIMEOUT` applies), existing heavy-route limit, client 300 ms debounce + abort (unchanged). Queries < 2 chars short-circuit with empty results before any network work (provider rule, not just ours); validation (trim, 200 cap, control-char reject) unchanged.
- **Merge strategy:** provider locations first in provider relevance order, then bundled event-index matches (`matchEventIndex` in `fallback.ts`, ids/behavior unchanged; `type=event` stays fully local and SIMULATED), sliced to `limit`. Dedupe by provider id then normalized name+country (first wins); deterministic — no scores compared. Per-result `source` (`Open-Meteo Geocoding` vs `bundled event index`/`bundled gazetteer`); envelope source names both when mixed. New optional `SearchResult` fields (`admin1`, `country_code`, `source`) are additive — existing clients ignore them.
- **Fallback order:** LIVE (cached 300 s in-memory + `public, s-maxage=300, stale-while-revalidate=600`) → expired LIVE re-served as STALE (`no-store`, `fetched_at` preserved) → bundled events as SIMULATED where they exist (`no-store`) → UNAVAILABLE empty (`no-store`). Cities/coordinates are never invented.
- **Reverse geocode (`src/app/api/v1/geocode/reverse/route.ts`):** explicit UNAVAILABLE with shape-stable null place fields. No compliant no-key provider fits: public Nominatim caps at 1 req/s *per application* aggregate (verified 2026-10-11, https://operations.osmfoundation.org/policies/nominatim/ — plus UA/attribution/ODbL terms and an autocomplete ban), which per-instance serverless state cannot enforce application-wide; Open-Meteo has no reverse endpoint. The old fabricated region generator (`reverseGeocodeMock`) is deleted. Heavy rate class unchanged; no upstream call is ever made.
- **Timezones (`src/server/providers/geocode.ts`, route `src/app/api/v1/timezones/route.ts`):** genuine offline IANA lookup via `@photostructure/tz-lookup` (pinned exact `11.7.0`, 0 deps, CC0-1.0, timezone-boundary-builder data; 73 KB self-contained module — no runtime data-file reads, so no serverless packaging risk; `geo-tz` rejected at ~70 MB + `data/`-read/bundler hazards). Replaces the 15°-slice approximation (which mislabelled Kolkata as Asia/Dhaka). UTC offset + wall-clock are computed live via `Intl` (DST-aware). Near-border coordinates resolve deterministically to one best match (border-exactness not claimed); offshore/uninhabited points return `Etc/GMT*` ocean zones; lookup failure → UNAVAILABLE (never the old approximation). LIVE + `no-store` (wall-clock payloads must stay fresh); no per-instance cache entry needed (in-process sync call). Standard rate class unchanged.
- **Request limits:** search + reverse stay `heavy` (20/60 s), timezones stays `standard` (60/60 s) — no limiter changes. Timeouts: geocoding reuses `OPEN_METEO_TIMEOUT` (default 8 s); timezone/reverse make no network calls.

## Real statistics and history (T2.7)

- **Overview (`GET /api/v1/stats`, `src/server/services/stats.ts`):** trailing-24h UTC window — `earthquakes_24h`/`max_magnitude_24h`/`max_magnitude_time` from USGS M2.5+ event records (finite mag + valid coords, same filter as the layer), `active_events` = unique EONET open events active in the trailing 30 days (`days=30` server-side recency — the unbounded all-time open set is 5000+ live, so it would make the headline a function of the request cap; cap hits are flagged as a lower bound, never a silent exact count), `wildfire_count`/`max_brightness` = keyed FIRMS `/WORLD/1` detection rows (observations, not distinct fires). Fabricated rollup fields (temperature anomaly, precipitation, AQI average, alerts, `by_region` severity) are removed — no UI consumed them and they had no provider.
- **Aggregate status rule (mirrors the T2.2 partial-coverage precedent):** all sources live → `live`; some live → `live` + message naming the unavailable sources (failed sources stay per-source-`unavailable` with null metrics — never implicitly live); none live → `unavailable` (stale re-serve first). Keyless/unreachable FIRMS → wildfire metrics null + `unavailable` (never simulated — a random count would invent detections).
- **History (`GET /api/v1/stats/historical?metric=&period=`, periods `24h|7d|30d`):** earthquakes = one USGS window query bucketed locally (24h → 24 hourly, 7d/30d → daily buckets of count/max/avg); disasters = one EONET `status=all` + inclusive `start`/`end` query bucketed by latest geometry date with `by_category` (each event once); wildfires = FIRMS `/WORLD/1|7` bucketed by UTC acquisition date/time (24h → hourly, 7d → daily). Buckets are `[start, end)` UTC-aligned; zero-count buckets carry null magnitudes (genuine zero ≠ unavailable). The old `aggregation` parameter is retired (granularity fixed by period); old periods `1y` and archiveless metrics (`temperature`, `air_quality`, 30d wildfires, keyless FIRMS) answer `UNAVAILABLE` with empty values — current values are never backfilled as history.
- **Bounds:** USGS `limit=20000` (service hard cap), EONET `limit=2000`, FIRMS rows capped at 200000 with a `truncated` flag surfacing as `warnings[]` (counts then a lower bound). One request per historical metric; 3 parallel single requests for the overview. Existing `USGS_TIMEOUT`/`EONET_TIMEOUT`/`FIRMS_TIMEOUT` overrides apply; no new fetch framework, no DB/queue.
- **Caching:** `stats:overview` and `stats:hist:<metric>:<period>` L1 keys (300 s) + `public, s-maxage=300` only when LIVE; everything else `no-store`. Rate classes unchanged (`standard`); validation allow-lists reject bad metric/period with 400 before any provider call.
- **EONET v3 contract fix (directly relevant defect, found by T2.7 live verification):** EONET serves event geometries under `geometry` (singular — verified against the live API + v3 docs), but `normalizeEonet` (`providers/nasa-eonet.ts`), `normalizeEonetEvent` (`services/event-detail.ts`), and all fixtures read `geometries` (plural), so every live EONET record was silently skipped — the disasters layer returned zero live points and live EONET detail degraded to null coordinates. All three call sites now go through `eonetGeometries()` (prefers `geometry`, accepts legacy `geometries`); regression tests pin the real v3 shape at the layer, stats, and detail levels. Fixtures that encoded the wrong key now use the real shape.

## Real heatmaps and imagery decisions (T2.8)

- **Sources (`src/server/providers/heatmap.ts`, decisions in `docs/audit/heatmap-decision.md`):** model layers sample genuine Open-Meteo `current=` estimates at cell centers (canonical variables: `temperature_2m` °C, `precipitation` mm, `cloud_cover` %, `wind_speed_10m` km/h, AQ `us_aqi`; multi-location lists paired by request order); event layers bin real observations per cell with the layer normalizers (USGS M2.5+ / EONET unique events / FIRMS detections over the `time_range` window: 24h→1d, 48h→2d, 7d→7d, 30d→30d; FIRMS day ranges stop at 10). Units: variable units for models, `count` for event grids. Seeded generation deleted — complete failure → stale → `UNAVAILABLE`, never simulated.
- **Grid + budget:** row-major equirectangular, width = served resolution, height = ceil(R/2); cell centers lon=-180+(c+0.5)*360/W, lat=90-(r+0.5)*180/H. At most 200 cells (`resolution` ≤ 20); higher requests are served at 20 with an in-band disclosed message (`> 512` still 400s); cache keys use the served resolution. Missing model cells are NaN (never zeros); event zeros inside covered windows are genuine. Worst supported payload measured 1,203 B raw / 558 B gzip (250 KB budget); base64-LE-float32 contract preserved. `HeatmapData` gains optional `warnings[]` (partial disclosure).
- **Caching:** `heatmap:<id>:res=<served>:range=<range>` L1 (3600 s, `HEATMAP_TTL` unchanged) + `public, s-maxage=3600` only when LIVE; else `no-store`. Rate class stays `heavy`; validation unchanged; existing per-provider timeouts + 50-point batches at concurrency 2.
- **Imagery:** GIBS WMTS REST pattern verified against official access-basics docs (matches `buildTileUrl`, y-before-x); 3 allow-listed daily `epsg4326/best` products documented per layer in the decision doc (true-color context + Band31-Day thermal visualization — pixels are never converted to measurements). Tile redirect + capabilities routes unchanged; CSP unchanged (`img-src 'self'`, report-only — no client tile loading, UI never calls GIBS). Globe overlay deferred (renderer rewrite out of scope; roadmap item).
- **Clouds:** globe cloud texture labelled illustrative (layer metadata + README); the numeric clouds heatmap is live model cloud-cover.

## Global air quality (T2.5)
- **Sources:** Open-Meteo Air Quality (`https://air-quality-api.open-meteo.com/v1`, override `OPEN_METEO_AQ_URL`) is the global model-based source — no key for standard non-commercial use, attribution to CAMS + Open-Meteo required. AirNow (`latLong/current`, key `AIRNOW_API_KEY`) stays as an optional U.S. station-observation source behind its existing fixed central-U.S. query (endpoint/params unchanged).
- **Selection (`getAirQualityData`, `src/server/providers/airnow.ts`):** U.S.-envelope bbox (lat 17–72, lon −180–−60) + key → try AirNow, fall through to the model on failure; anything else (global, non-U.S., straddling, or keyless) → model directly; model failure → labelled `SIMULATED` via the established stale policy. No per-point AirNow fan-out: the AirNow docs' bbox observation feeds were not verifiable from here, so key-bearing requests stay at one fixed query per AQ request (plus T1.3 limits + 1800 s shared cache).
- **Model vs stations:** `data_status.source` is `Open-Meteo Air Quality` or `AirNow` per request; model messages state "estimates, not monitoring-station observations", AirNow messages state "monitoring-station observations". Requested variables: `us_aqi, pm2_5, pm10, ozone, nitrogen_dioxide` only. Points keep the layer contract (`aqi-<lat>-<lon>`, US-AQI `value`, `severityForAqi`, `parameter: "AQI"`) plus `pollutants` (`null` for omitted values, never zeros); missing `us_aqi` skips the point. No worldwide station coverage is claimed — outside AirNow, values are CAMS model estimates.
- **Sampling:** weather grid (108 global / 100 bbox, cap 200, 50-point batches) over the shared `runBatches` pool (`src/server/batch-pool.ts`, concurrency 2, per-batch `OPEN_METEO_TIMEOUT`). Multi-location responses (a list, unlike single-location objects) pair by request order; requested grid coordinates are kept so markers stay stable when the model echoes a nearby cell center. Grid spacing dwarfs the ~45 km cells, so no dedup pass is needed.
- **Freshness:** model `timestamp` is the feed's `current.time`, `fetched_at` the fetch time; AirNow points carry feed time (`utcnowIso` at normalize). AirNow TTL, cache policies, timeouts, and rate-limit classes are unchanged (air_quality TTL stays 1800; LIVE → public, else `no-store`).

## Real-time solar position (T2.4)

- **Pure calculation (`src/lib/solar.ts`, no React/DOM/timers/network):** `getSubsolarPoint(date)` implements a low-precision solar ephemeris (J2000 mean longitude/anomaly + equation-of-center + obliquity → declination; GMST − right ascension → hour-angle longitude, which embeds the equation of time — solar noon is NOT assumed at 12:00 UTC, equinox latitude is NOT assumed 0). `subsolarPointToSunDirection` converts to the renderers' world-space vector; `getSunDirection` is the one-step single source. Invalid dates throw `TypeError` (never a silent 0/0 terminator).
- **Accuracy:** cross-checked against the independent NOAA day-angle series at 2026-03-20 / 06-21 / 12-21 12:00 UTC (values + method pinned in `src/lib/solar.test.ts`): worst deviation ≈ 0.25°, inside the PRD's ≈ 1° terminator budget with ~4× margin. Residual limits: truncated periodic terms (dominant, < 0.5°), ignored nutation/aberration (< 0.01°) and UTC-vs-terrestrial-time (< 0.02°).
- **Convention:** vector FROM Earth's centre TOWARD the subsolar point, projected exactly as `latLonToVec3` (`src/lib/geo.ts`, three-free plain math since T4.5): equator/prime-meridian → +X, north pole → +Y. WebGPU feeds it to the TSL day/night `dot()` blend + directional light; WebGL feeds it to its directional light position (previously a hardcoded `[10,5,10]` that ignored the prop entirely — the WebGL night-lights overlay itself is still a constant additive shell, so only the lit-side shading tracks the Sun there; no shader rewrite was in scope).
- **One shared tick (`src/hooks/useSunDirection.ts`, consumed once in `SentinelApp`):** deterministic `DEFAULT_SUN_DIRECTION` (`src/components/globe/earthConfig.ts`) for SSR/first render (hydration-identical), live UTC value after mount, single 60 s `setInterval` (`SUN_DIRECTION_UPDATE_INTERVAL_MS`), cleared on unmount. No per-renderer timers; the tuple identity changes at most once per minute so the memoized renderer stays settled. The Sun drifts ≈ 0.25°/min, so 60 s keeps the terminator well inside budget. Globe auto-rotation / fly-to / camera behaviour untouched.
- **Tests:** `src/lib/solar.test.ts` (18: NOAA reference vectors, hemispheres, UTC-hour shift, normalization sweep, leap-day/boundary, invalid dates, conversion parity, sign/axis), `src/hooks/useSunDirection.test.tsx` (4: interval value, SSR determinism, mount + 60 s refresh,   cleanup), `src/components/globe/EarthRenderer.test.tsx` (3: identical authoritative tuple reaches both the WebGPU and WebGL branches).

## Rate limiting (T1.3)

Enforced in `src/middleware.ts` (matcher `/api/v1/:path*`) via the token bucket in `src/server/rate-limit.ts` — light 120 / standard 60 / heavy 20 requests per 60 s per client IP (route classes in `classifyRoute()`). Throttled callers get `429` + the standard `{ success: false, error: { code: "RATE_LIMITED", … } }` envelope + `Retry-After`, before any provider call. The store is hard-bounded (`MAX_ENTRIES=2000`, expiry + oldest-first eviction) and Edge-safe (no Node APIs).

Know the limits of this layer — it is per isolate/region, not global:

1. **Prefer Vercel-native enforcement when the plan allows it.** There is no `vercel.json` firewall config in this repo (WAF/rate-limit rules are plan-gated and dashboard-managed, not code). Recommended rule once available: match `/api/v1/layers/*/data`, `/heatmap`, `/search`, `/geocode/*`, `/imagery/gibs/tile/*` with a stricter threshold than the metadata routes, action `rate_limit`/`block`, and keep this in-process limiter as defense-in-depth. No paid upgrade was made for T1.3.
2. **Do not trust `x-forwarded-for` blindly off-platform.** On Vercel it is platform-appended (first entry = client). Direct-to-origin traffic could spoof it — the bounded store caps the blast radius to slot churn, not memory growth.
3. **Unidentifiable clients share one `unknown` bucket** — they are limited together, never exempt.
4. No Redis/Upstash/database was added; none is needed for this abuse-control tier.

## Content Security Policy (T1.2, CSP-1)

- **Effective report-only policy** (`next.config.mjs`, one `/:path*` rule for `/`, `/api/*`, assets): `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self'; img-src 'self'; connect-src 'self'; font-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'` via `Content-Security-Policy-Report-Only`, plus `nosniff`, `strict-origin-when-cross-origin`, deny-list `Permissions-Policy`, `DENY` framing. Report-only on purpose — enforcing is a separate later task after zero violations. Pinned by `src/server/security-headers.test.ts`.
- **Diagnosis of the `localhost:3000` console messages (all traced in source, Next 15.5.27):**
  - `upgrade-insecure-requests` ignored in report-only → **invalid/ineffective configuration (fixed):** removed from the report-only header in CSP-1; reserved for the future enforced policy. Guard test fails if it returns.
  - Inline-`style` reports on first paint → **application-authored, fixed where static:** the static SSR shell emitted `style="..."` (root background, renderer veils, mobile-rail scrollbar rule, renderer dot). CSP-1 moved all of them to Tailwind classes / a `data-renderer-dot` token rule; `src/app/page.test.tsx` now pins zero `style="` attributes in SSR HTML. Runtime React/CSSOM sets (`canvas.style.cursor`, hover-card position, motion values) are policy-clean by construction and were not changed.
  - Remaining inline-style surface → **legitimate dynamic values, intentionally kept:** provenance dot/label colors (`StatusDock`, `AppHeader`, `DataStatusBanner`), severity colors, hover-card position/border, distribution flex ratios, grid column counts, result-type icon chips. These render client-side via CSSOM (no report); they appear in markup only if a future SSR path renders them. Fixing them would need `'unsafe-inline'` (rejected), hashes (do not apply to style attributes, per the browser warning), or a per-request nonce (rejected: breaks the static `/` route + caching — see T3.2). Trade-off recorded here instead of weakening the policy.
  - `unsafe-eval` report → **Next.js development runtime (documented, policy untouched):** zero `eval`/`new Function`/`dangerouslySetInnerHTML`/dynamic style injection exists in `src` (grep-verified); `next dev` HMR/Refresh evaluates code in dev only. No `'unsafe-eval'` was added. **Owner check:** confirm no eval report on the production build (`next start`) — that is the only environment the policy judges.
  - Charts/globe engines (three, R3F/drei, visx, motion, Radix) → **third-party, no action:** chart components render exclusively through `ValueHistogram` (`ssr:false`), so their style props never reach SSR markup; no `<style>` injection or eval found in app-reachable paths. DottedEarth sizes via CSS classes + canvas backing-store attributes; only `cursor` is set at runtime.
  - React DevTools "Download …" notice → **development informational message**, not a CSP violation; no action.
  - Browser-extension injection → **unconfirmed:** cannot be ruled out headlessly; if style/eval reports persist in production after this pass, re-check with extensions disabled before touching the policy.
- **What a green build does NOT prove:** unit tests + header smoke checks confirm the policy ships, not that the console is silent — violation reports only exist in a real browser. Console silence stays an owner-manual check.

## Charts — why `@visx/*` stays on alpha (P1-1 decision)

All seven `@visx/*` packages are pinned **exact** (`4.0.1-alpha.0`, no caret) in `package.json`. Rationale: the set is internally consistent, lockfile-pinned, `npm ls` peer-clean, and covered by `ValueHistogram` tests — while the newest stable (`4.0.0`) is OLDER than the installed alpha (a `4.0.1` prerelease), so "migrating to stable" would be a downgrade with unknown visual/API regressions. Do not replace visx (no Bklit migration) without a separate owner-approved product decision. Revisit only if a real incompatibility or a stable `≥4.0.1` appears.
